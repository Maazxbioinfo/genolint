# GL003 — `bcftools view` with both `-r` and `-R`

## What it catches

`bcftools view` offers two ways to restrict output to specific genomic
regions:

- `-r`/`--regions` — a comma-separated list of regions given directly on
  the command line
- `-R`/`--regions-file` — a file (BED or tab-delimited) listing regions

They're alternative ways of specifying the *same* thing, and bcftools
does not merge them — passing both is either redundant, contradictory, or
simply a mistake (often from copy-pasting a command template and
forgetting to delete the flag that's no longer needed):

```bash
# Flagged: both -r and -R given
bcftools view -r chr20:1-1000000 -R regions.bed input.vcf.gz
```

## Why it matters

This is almost always leftover from editing a command (switching from an
inline region to a regions file, or vice versa, without removing the old
flag). At best it's harmless because one silently wins; at worst it's
confusing about which regions are actually being used, and it signals the
command wasn't re-read after editing.

## The fix

Keep exactly one of the two:

```bash
# GOOD — inline region
bcftools view -r chr20:1-1000000 input.vcf.gz

# GOOD — regions file
bcftools view -R regions.bed input.vcf.gz
```

## When to ignore it

There isn't a legitimate reason to pass both `-r` and `-R` to the same
`bcftools view` invocation — bcftools itself doesn't define combined
semantics for it. If you find a genuine, intentional use of both flags
together, please treat that as a case worth reporting back to the
project rather than a false positive to quietly suppress, since it would
mean the tool's documented behavior differs from what GL003 assumes.
