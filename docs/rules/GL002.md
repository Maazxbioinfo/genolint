# GL002 — `bcftools concat` without `-a`

## What it catches

`bcftools concat` joins VCF/BCF files that are expected to contain
non-overlapping sets of records (classically, one file per chromosome).
By default it assumes the inputs don't overlap in position and simply
appends them in the order given. If your inputs *do* overlap — for
example, separate SNP-only and indel-only call sets covering the same
regions, or files split by variant type rather than by chromosome — you
need `-a`/`--allow-overlaps` (which also requires/behaves best with
coordinate-sorted, indexed inputs) so `concat` merges and sorts records
correctly instead of just gluing files together.

GL002 flags a `bcftools concat` call that has no `-a`:

```bash
# Flagged: no -a
bcftools concat snps.vcf.gz indels.vcf.gz -o merged.vcf.gz
```

## Why it matters

Without `-a` on overlapping inputs, the concatenated file can end up with
records out of coordinate order, which breaks downstream tools that
assume sorted VCF (indexing, region queries, many variant annotators).
This is the second bug class from the real history genolint was validated
against: a `04_filtering.sh`-style script concatenating per-type
(SNP/indel) call sets without `-a`.

## The fix

Add `-a` when inputs can overlap:

```bash
# GOOD
bcftools concat -a snps.vcf.gz indels.vcf.gz -o merged.vcf.gz
```

## When to ignore it (built-in exceptions)

GL002 already suppresses itself in the two cases where inputs are
guaranteed non-overlapping by construction, since `-a` is unnecessary
(and sometimes actively unwanted) there:

- **Per-chromosome inputs** — if the file list/arguments look like a
  per-chromosome split (e.g. `chr1.vcf.gz chr2.vcf.gz ...` or
  `part.20.vcf.gz`, `part.21.vcf.gz`), genolint treats this as the
  classical non-overlapping case and does not flag it.
- **`-f file-list`** — when concat is driven by a file list via `-f`,
  genolint can't inspect the individual filenames to judge overlap, so it
  assumes the list was constructed correctly and skips the check rather
  than guess.

If you hit a case where the auto-detection misfires — e.g. a
per-chromosome naming scheme genolint doesn't recognize — treat that as a
genolint false negative/positive to report rather than something to
silently work around; it's useful validation data (see the project's
"messier corpus" validation step).
