# GL006 — Region query (`-r`/`-R`) on a VCF/BCF with no prior index step

## What it catches

Random-access region queries against a VCF/BCF — `-r`/`--regions` and
`-R`/`--regions-file` on tools like `bcftools view`/`bcftools query` —
require the file to be indexed (a `.tbi`/`.csi` alongside a bgzipped
file, or an equivalent). Without an index, tools either fail outright or
(depending on the tool/version and whether `--regions-overlap`/streaming
mode kicks in) silently fall back to a slower linear scan — behavior that
varies enough across tools and versions that it's safer to just always
index first.

GL006 flags a command using `-r`/`-R` on a VCF/BCF where the script has no
earlier step that indexes that file — no `bcftools index`, no `tabix`,
and no `--write-index` on the command that produced it:

```bash
# Flagged: region query on a file with no visible indexing step
bcftools view -r chr20:1-1000000 input.vcf.gz -o subset.vcf.gz
```

## Why it matters

This is the class of bug that "works on my machine" and then fails (or
silently degrades to a slow scan) somewhere else — on a fresh clone of a
pipeline, in CI, on a collaborator's machine, or after a file gets
recreated without carrying its index along. Because the failure mode
isn't always a hard error, it's easy to miss in casual testing and only
show up as an unexplained slowdown or an outright crash later.

## The fix

Add an explicit indexing step before the region query, or index at
creation time:

```bash
# GOOD — index, then query
bcftools index input.vcf.gz
bcftools view -r chr20:1-1000000 input.vcf.gz -o subset.vcf.gz

# GOOD — write the index as part of creating the file
bcftools view -Oz --write-index -o input.vcf.gz unindexed_input.bcf
bcftools view -r chr20:1-1000000 input.vcf.gz -o subset.vcf.gz
```

## When to ignore it

- If the file is indexed by an earlier step genolint can't see — e.g. a
  separate script/Makefile target, a step outside the file(s) you're
  linting, or an index shipped alongside a downloaded reference file —
  this is a safe finding to dismiss for that script.
- If you're intentionally relying on a tool's linear-scan fallback for a
  one-off/small file and have confirmed that's safe for your tool
  version, that's also a reasonable case to dismiss, though indexing is
  cheap enough that it's usually simpler to just add the step.
